## Q1
- Prediction / 预测: For FIFO and SJF, Avg Response 200.00, Avg Turnaround 400.00, Avg Wait 200.00 / FIFO和SJF的平均响应时间200.00，平均周转时间400.00，平均等待时间200.00
- Reasoning / 理由: The three jobs have equal length (200), so SJF has nothing to reorder and behaves exactly like FIFO. Jobs finish at 200, 400, 600 and first run at 0, 200, 400. / 三个作业长度相同(200)，SJF没有可重排的对象，行为与FIFO完全一致。完成时间为200、400、600，首次运行时间为0、200、400。
- Verified result / 验证结果: Both FIFO and SJF: Avg Response 200.00, Avg Turnaround 400.00, Avg Wait 200.00 / FIFO和SJF均为：平均响应时间200.00，平均周转时间400.00，平均等待时间200.00
- Analysis / 分析: The prediction matched exactly. With equal job lengths, SJF has no shorter job to prefer, so it produces the same schedule as FIFO. This shows SJF only helps when job lengths differ. / 预测完全准确。作业长度相同时，SJF找不到更短的作业可以优先，所以调度结果与FIFO相同。这说明SJF只有在作业长度不同时才有优势。

## Q2
- Prediction / 预测: For FIFO and SJF, Avg Response 133.33, Avg Turnaround 333.33, Avg Wait 133.33 / FIFO和SJF的平均响应时间133.33，平均周转时间333.33，平均等待时间133.33
- Reasoning / 理由: The jobs (100, 200, 300) are already submitted shortest-first, so SJF runs them in the same order as FIFO. First-run times are 0, 100, 300 and completion times are 100, 300, 600. / 作业(100、200、300)本来就是按从短到长的顺序提交的，所以SJF的执行顺序与FIFO相同。首次运行时间为0、100、300，完成时间为100、300、600。
- Verified result / 验证结果: Both FIFO and SJF: Avg Response 133.33, Avg Turnaround 333.33, Avg Wait 133.33 / FIFO和SJF均为：平均响应时间133.33，平均周转时间333.33，平均等待时间133.33
- Analysis / 分析: The prediction matched exactly. Because the jobs were already in shortest-first order, SJF and FIFO produced identical schedules. Note that response time (133.33) is much higher than in the equal-length case relative to job size, because later jobs must wait for all earlier jobs to finish. / 预测完全准确。因为作业本来就是从短到长排列，SJF与FIFO的调度结果完全相同。后面的作业必须等前面所有作业跑完才能开始，所以响应时间会随着前面作业的累积长度而增大。

## Q3
- Prediction / 预测: For RR with quantum 1 on jobs 100,200,300: Avg Response 1.00, Avg Turnaround 465.67, Avg Wait 265.67 / RR时间片为1，作业100、200、300：平均响应时间1.00，平均周转时间465.67，平均等待时间265.67
- Reasoning / 理由: Jobs first run at times 0, 1, 2, so response is 0, 1, 2 (avg 1.00). With three jobs sharing the CPU, job 0 finishes at 298; then two jobs alternate and job 1 finishes at 499; job 2 runs alone and finishes at 600. Turnaround is 298, 499, 600 (avg 465.67), and wait = turnaround - length = 198, 299, 300 (avg 265.67). / 三个作业首次运行时间为0、1、2，所以响应时间为0、1、2（平均1.00）。三个作业共享CPU时，作业0在298结束；之后两个作业交替运行，作业1在499结束；作业2独自运行，在600结束。周转时间为298、499、600（平均465.67），等待时间=周转时间-作业长度=198、299、300（平均265.67）。
- Verified result / 验证结果: RR (quantum 1): Avg Response 1.00, Avg Turnaround 465.67, Avg Wait 265.67; per-job turnaround 298, 499, 600 / RR(时间片1)：平均响应时间1.00，平均周转时间465.67，平均等待时间265.67；各作业周转时间为298、499、600
- Analysis / 分析: The prediction matched exactly. Compared with FIFO/SJF (response 133.33, turnaround 333.33), RR gives a far better average response time but a worse average turnaround time. This is the classic trade-off: RR is fair and responsive because every job gets the CPU quickly, but it stretches out every job's completion. / 预测完全准确。与FIFO/SJF（响应时间133.33、周转时间333.33）相比，RR的平均响应时间好得多，但平均周转时间更差。这就是经典的权衡：RR让每个作业都能很快拿到CPU，公平且响应快，但会拖长每个作业的完成时间。

## Q4
- Prediction / 预测: SJF gives the same turnaround time as FIFO when jobs are submitted in non-decreasing order of length (shortest first), including the case where all jobs have equal length, assuming all jobs arrive at the same time. / 当所有作业同时到达，且作业按长度从短到长（非递减）的顺序提交时（包括所有作业长度相同的情况），SJF的周转时间与FIFO相同。
- Reasoning / 理由: FIFO runs jobs in submission order and SJF runs the shortest first. If the submission order is already shortest-first, both produce the same order, so every job has the same completion time. If a long job comes first, FIFO makes the short jobs wait behind it (convoy effect) while SJF does not. For example, with jobs 300,200,100, FIFO should give avg turnaround 466.67 and SJF 333.33. / FIFO按提交顺序运行，SJF先运行最短的作业。如果提交顺序本来就是从短到长，两者的执行顺序相同，每个作业的完成时间也相同。如果长作业排在最前面，FIFO会让短作业排在它后面等待（护航效应），而SJF不会。例如作业为300、200、100时，FIFO的平均周转时间应为466.67，SJF应为333.33。
- Verified result / 验证结果: Jobs 300,200,100: FIFO Avg Turnaround 466.67 (Response 266.67), SJF Avg Turnaround 333.33 (Response 133.33). With sorted jobs (Q2) both gave 333.33. / 作业300、200、100：FIFO平均周转时间466.67（响应时间266.67），SJF平均周转时间333.33（响应时间133.33）。作业已排序时(Q2)两者都是333.33。
- Analysis / 分析: The prediction matched exactly. When the longest job comes first, FIFO delays all shorter jobs behind it (convoy effect), while SJF does not, so their turnaround times differ. The two only coincide when jobs are already ordered shortest-first. / 预测完全准确。最长的作业排在最前面时，FIFO会让所有较短的作业都排在它后面等待（护航效应），而SJF不会，所以两者的周转时间不同。只有作业本来就从短到长排列时，两者才相同。

## Q5
- Prediction / 预测: SJF and RR give the same response time when jobs are submitted shortest-first and the quantum is at least as long as every job except possibly the longest one (in the simplest case, quantum >= all job lengths, so RR never preempts). / 当作业按从短到长提交，且quantum不小于除最长作业之外的每个作业的长度时（最简单的情况是quantum不小于所有作业长度，此时RR不会发生抢占），SJF与RR的响应时间相同。
- Reasoning / 理由: A job's response time is the time spent by earlier jobs before it first runs. Under SJF that is the sum of earlier job lengths; under RR it is the sum of min(quantum, length) over earlier jobs. These are equal exactly when every earlier job is no longer than the quantum. For jobs 100,200,300, quantum 200 should give RR avg response 133.33, equal to SJF, while quantum 100 should give 100.00, which differs. / 作业的响应时间是它首次运行之前，排在它前面的作业所占用的时间。SJF下是前面作业长度之和；RR下是前面每个作业min(quantum, 长度)之和。当且仅当前面每个作业都不超过quantum时两者相等。对于作业100、200、300，quantum为200时RR平均响应时间应为133.33，与SJF相同；quantum为100时应为100.00，两者不同。
- Verified result / 验证结果: Jobs 100,200,300: RR with quantum 200 gives Avg Response 133.33 (same as SJF); RR with quantum 100 gives Avg Response 100.00 (differs from SJF). / 作业100、200、300：RR的quantum为200时平均响应时间133.33（与SJF相同）；quantum为100时平均响应时间100.00（与SJF不同）。
- Analysis / 分析: The prediction matched exactly. With quantum 200, jobs 0 and 1 (lengths 100 and 200) are not longer than the quantum, so RR never preempts them before the next job starts and behaves like SJF for response time. With quantum 100, job 1 is preempted, so job 2 starts earlier (at 200 instead of 300) and RR's response time becomes smaller than SJF's. / 预测完全准确。quantum为200时，作业0和作业1（长度100和200）都不超过quantum，RR在下一个作业开始前不会打断它们，响应时间表现与SJF相同。quantum为100时，作业1被打断，作业2更早开始（在200而不是300），RR的响应时间就比SJF更小。

## Q6
- Prediction / 预测: As job lengths increase, SJF's response time increases proportionally (linearly). For jobs 10,20,30 / 100,200,300 / 1000,2000,3000, the average response time should be 13.33 / 133.33 / 1333.33. / 随着作业长度增加，SJF的响应时间成比例（线性）增大。对于作业10、20、30 / 100、200、300 / 1000、2000、3000，平均响应时间应分别为13.33 / 133.33 / 1333.33。
- Reasoning / 理由: SJF is non-preemptive, so a job cannot start until all shorter jobs ahead of it have run to completion. Its response time is therefore the sum of the lengths of the jobs before it. If every job length is multiplied by 10, every response time is also multiplied by 10. / SJF不可抢占，所以一个作业必须等排在它前面的所有更短的作业完整跑完才能开始。它的响应时间就是前面作业长度之和。如果每个作业的长度都乘以10，每个响应时间也乘以10。
- Verified result / 验证结果: SJF avg response time: 13.33 (jobs 10,20,30), 133.33 (jobs 100,200,300), 1333.33 (jobs 1000,2000,3000). / SJF平均响应时间：作业10、20、30为13.33；作业100、200、300为133.33；作业1000、2000、3000为1333.33。
- Analysis / 分析: The prediction matched exactly. Each 10x increase in job length produced exactly a 10x increase in average response time, confirming a linear relationship. This is a weakness of SJF: because it is non-preemptive, long jobs ahead in the queue make every later job wait longer, so SJF is poor for response time. / 预测完全准确。作业长度每增大10倍，平均响应时间恰好增大10倍，证实了线性关系。这是SJF的弱点：由于不可抢占，排在前面的长作业会让后面所有作业等待更久，所以SJF的响应时间表现不好。

## Q7
- Prediction / 预测: As the quantum increases, RR's response time increases, until the quantum is at least as long as the jobs, at which point RR behaves like FIFO and stops getting worse. Worst-case response time for N jobs arriving together with quantum q is (N-1) * q. For 3 jobs of length 100, avg response should be 1.00, 10.00, 50.00, 100.00 for q = 1, 10, 50, 100. / 随着quantum增大，RR的响应时间增大，直到quantum不小于作业长度，此时RR等同于FIFO，不再变差。N个作业同时到达、quantum为q时，最坏响应时间为(N-1)*q。对于3个长度为100的作业，q=1、10、50、100时平均响应时间应分别为1.00、10.00、50.00、100.00。
- Reasoning / 理由: Under RR, a job must wait for every job ahead of it to run one full quantum before it first runs. So the last job waits (N-1) * q, and the response times of 3 equal jobs are 0, q, 2q (average q). A larger quantum makes each wait longer. Once q is at least the job length, each job finishes in one turn, so there is no further increase. / 在RR下，一个作业必须等排在它前面的每个作业各完整运行一个quantum后才能第一次运行。所以最后一个作业要等(N-1)*q，3个等长作业的响应时间为0、q、2q（平均q）。quantum越大，每次等待越久。一旦q不小于作业长度，每个作业一轮就能跑完，响应时间不会再继续增大。
- Verified result / 验证结果: Jobs 100,100,100 with RR: quantum 1 / 10 / 50 / 100 gives Avg Response 1.00 / 10.00 / 50.00 / 100.00 and Avg Turnaround 299 / 290 / 250 / 200. / 作业100、100、100使用RR：quantum为1 / 10 / 50 / 100时，平均响应时间为1.00 / 10.00 / 50.00 / 100.00，平均周转时间为299 / 290 / 250 / 200。
- Analysis / 分析: The prediction matched exactly. Average response time equals q, consistent with response times 0, q, 2q and the worst case (N-1) * q = 2q for N = 3. At q = 100 (equal to the job length) RR behaves like FIFO. Interestingly, a larger quantum also improves average turnaround time (299 down to 200), because jobs are interrupted less and finish earlier; so the quantum is a trade-off between responsiveness and turnaround time. / 预测完全准确。平均响应时间等于q，与响应时间0、q、2q以及N=3时最坏情况(N-1)*q=2q一致。q=100（等于作业长度）时RR的行为与FIFO相同。有趣的是，quantum变大时平均周转时间也变好了（从299降到200），因为作业被打断得更少、完成得更早；所以quantum是在响应速度和周转时间之间的权衡。
